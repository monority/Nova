# Kit de session de jeu — Step048 volet B

**Objectif** : consigner tes frictions de joueur, pour arbitrer les
priorités de tuning à venir. Une seule partie suffit ; deux vaut mieux.
Pas de protocole — une liste à puces libre, datée.

## Lancer le jeu

```
pnpm dev        # puis ouvrir l'URL affichée (Vite)
```

Astuce mesure : les événements se règlent dans la barre du bas
(« Events: off » → clic pour activer, « Frequency: » pour le curseur).
Recommandé pour une première partie : **off** (tu joues le jeu de base) ;
seconde partie : **frequent** (tu sens l'aléa post-Step049).

## Ce qu'il faut relever (au fil de l'eau, pas après coup)

1. **Moments d'hésitation** : quand tu ne sais pas quoi construire
   ensuite, et pourquoi (manque d'information ? pas d'option
   intéressante ? trop d'options ?).
2. **États incompris** : une alerte, un overlay ou un chiffre que tu as
   dû deviner. Citer le texte exact affiché.
3. **Impasses** : un moment où la partie te semble bloquée ou sans
   rebond (crise d'argent, famine, attente passive trop longue).
4. **Curseurs jamais touchés** : un bouton/panneau que tu n'as pas
   ouvert de toute la partie.
5. **Le positif** : ce qui a été satisfaisant — à ne pas casser.

## Format de remise

Liste libre dans `docs/roadmap/` (ex. `Step048-playtest-notes.md`) ou
n'importe où — je la transcoderai en entrées du report. Chaque item :
`[moment approx. — tick/âge si visible] description`.

## Ce que je ferai avec

Chaque friction devient une ligne du report Step048 (§ volet B) avec,
si elle est mesurable, la donnée correspondante du harnais — puis
arbitrage des priorités de tuning avec toi.
