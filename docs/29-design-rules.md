# NOVA — Design Rules

1. Causality beats content volume.
2. The simulation owns truth.
3. Infrastructure is not automatically a service.
4. Operational state is not automatically satisfied demand.
5. A service is not automatically a satisfied need.
6. Population needs a reason to exist and grow.
7. Resources need producers and consumers.
8. Every shortage must have a measurable consequence.
9. Major consequences need an understandable explanation.
10. Time changes simulation state, not merely animations.
11. Determinism is a product feature.
12. Save games represent canonical state.
13. Rendering never invents simulation facts.
14. Complexity is earned by dependencies.
15. One implementation step should introduce one coherent causal relationship.
16. Do not create a system merely because another simulation has one.
17. Vehicles come after transport demand.
18. Technology comes after constraints worth solving.
19. Decorative content must not masquerade as simulation.
20. Stable ordering is required whenever multiple valid outcomes exist.
21. New abstractions require a concrete current use case.
22. A blocked verification must remain visible.
23. Existing code is not automatically authoritative; validated behavior is.
24. Preserve useful infrastructure during the reset instead of rewriting it for aesthetic reasons.
25. The MVP must prove a vertical causal loop before broadening the simulation.
