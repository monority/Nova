# NOVA — City Simulation

## 1. Simulation Model

The simulation is a deterministic discrete-time system.

```text
Input Commands
    ↓
Simulation Tick
    ↓
Infrastructure
    ↓
Population
    ↓
Production / Consumption
    ↓
Construction
    ↓
Technology
    ↓
Events
    ↓
Derived Metrics
```

## 2. Fixed Timestep

Use the canonical simulation contract: one tick is one in-game day, 30 ticks are one month and 360 ticks are one year. Exact formulas, starting values and limits are defined in [20-product-contract.md](./20-product-contract.md).

```ts
type SimulationTick = number
type SimulationTime = {
  day: number
  year: number
}
```

Speed changes how many ticks are processed per real second, not the mathematical behavior of a tick.

## 3. Dependency Order

Systems must have explicit ordering.

```text
1. Commands
2. Terrain/accessibility
3. Production
4. Consumption
5. Population
6. Construction pressure
7. Building state
8. Technology placeholders
9. Events
10. Metrics and state hash
```

Avoid hidden cross-system mutation.

## 4. Determinism

All simulation randomness uses a seeded PRNG.

Never use unseeded `Math.random()` inside simulation logic.

## 5. City Metrics

Core derived metrics:

- population;
- housing capacity;
- employment;
- food balance;
- energy balance;
- material balance;
- average satisfaction;
- road accessibility;
- traffic pressure;
- technology progress.

## 6. Growth

Population growth is influenced by:

```text
Housing availability
× Food security
× Health
× Employment
× Satisfaction
```

Growth must be bounded and gradual.

The MVP uses the fixed wellbeing formula, starting population and growth clamp in [20-product-contract.md](./20-product-contract.md). This prevents each system from inventing a different population model.

## 7. Construction

Construction pressure is generated by unmet demand and available capacity.

```text
Demand
+
Accessible land
+
Resources
+
Workers
=
Construction opportunities
```

The builder then selects valid parcels deterministically.

## 8. Simulation Invariants

Examples:

- population cannot be negative;
- resource storage cannot exceed capacity unless overflow is explicitly modeled;
- buildings occupy valid parcels;
- roads remain topologically connected when their endpoints are valid;
- technology cannot regress in the base game;
- saved state must resume deterministically.

## 9. Scalability

Use aggregate population groups and resource flows.

Do not simulate hundreds of thousands of individual citizens in the MVP.

The MVP release gate is 500 completed buildings. 1,000 buildings is a stretch target only.
